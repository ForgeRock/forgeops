# Release Notes

## Kustomize deprecation

Support for Kustomize-based deployments is deprecated. Users should migrate to Helm chart-based deployments.  
You can use the <a href="how-tos/migrate-kustomize-to-helm.md">Migrate Kustomize to Helm</a> guide in the ForgeOps repository.

Deprecated in: 2026.3.2

Expected removal: 12 months after 2026.3.2 release

## New Features/Updated functionality

### Alpine-based platform images selectable with platform.imageMode

The platform components (DS, IDM, IG, admin-ui, end-user-ui, login-ui, amster, AM) can now run the
Alpine-based images from the new image CI line. Setting `platform.imageMode: forgeops` in the
identity-platform chart values switches every product at once: pods run as the pingbase uid (9031),
the home directory is `/home/ping`, and each product's ConfigMaps use the POSIX script variants.
The default mode (`base`) is unchanged: Debian images, uid 11111.

Every product image is now resolved through a single chart helper: `platform.imageRepository`
plus a per-component image name, with optional per-component `repository`, `name`, and `tag`
overrides in values.yaml. A `sha256:...` tag renders as a digest reference
(`repository@sha256:...`).

### New RCS Helm chart

A new `charts/rcs` chart deploys the Ping Remote Connector Server in server or client mode:
headless service on port 8759, optional NetworkPolicy allow-listing (`remoteIps`),
ConfigMap-driven `ConnectorServer.properties` and logback configuration, custom connector
libraries, and an optional `rcs-certs` truststore. In server mode the shared `rcs-key` secret is
generated by default; the entrypoint derives the connector-server key from `RCS_KEY_PASSWORD`
(or accepts a pre-computed `RCS_KEY`).

### RCS registers with IDM automatically

When the identity-platform and rcs charts deploy to the same namespace, IDM registers the RCS
out of the box — no manual steps. An optional sample LDAP provisioner
(`platform.rcs.provisioner.enabled`) exposes the deployment's own DS idrepo userstore through
the RCS, giving the admin UI a working Connectors entry and a base for sync setup. Stale
registration files are cleaned up on restart when the RCS wiring is off; deployer-supplied
connector configs are left alone.

### ping-gateway ingress forwards the full path (no rewrite-target)

The `ig` ingress now uses a plain `Prefix` path and no longer sets `rewrite-target`: the IG
image strips the `/ig` prefix itself, so ingress controllers that ignore nginx rewrite
annotations work unchanged. `/igadmin` keeps its previous regex + rewrite behavior on a separate
`ig-admin` Ingress. If you override `ig.ingress.annotations` yourself, do not set
`rewrite-target`, or requests will be double-prefixed.

## Bugfixes

### DS init no longer logs add-schema errors on ds-cts

The DS entrypoint ran the per-pod `add-schema` script unconditionally, logging
`No such file or directory` on every ds-cts boot. add-schema ships for ds-idrepo only; the call
is now guarded.

### ds-idrepo read the wrong values for IMAGE_MODE

The ds-idrepo StatefulSet scanned `ds_cts.env` instead of `ds_idrepo.env` when deciding whether
to inject `IMAGE_MODE`, so a deployer-supplied IMAGE_MODE could not override it. The chart's DS
entrypoint ConfigMap is also only mounted in forgeops mode now, so base-mode deployments keep
using the entrypoint baked into their image.

### DS snapshot cron job works on busybox and releases cloned PVCs

`snapshot.sh` used GNU-date-only invocations and a redirection instead of a comparison
(`[ $# > 0 ]`), so on the busybox cronjob image the purge loop was broken. The script now
detects the date implementation and parses the documented relative expressions
(`last day`, `last hour`, `-10 min`) on busybox. The backup job is also deleted after a
successful snapshot so the cloned PVC is released.

### rcs chart hardening

* The StatefulSet now sets `serviceName` (required before Kubernetes 1.34, and what provides
  per-pod DNS)
* Secret volumes are readable by the non-root runtime uid (mode 0444)
* The NetworkPolicy uses the chart's own selector, admits same-namespace consumers alongside
  `remoteIps`, and allows DNS over TCP
* A `checksum/config` annotation rolls the pods when the rendered config changes
* `RCS_KEY` is JSON-escaped before being written into IDM's registration config
* `capabilities.drop` uses Kubernetes' `ALL` token instead of the invalid `All`
* The chart-publish workflow can no longer publish the placeholder-versioned platform charts or
  a broken chart from an unreadable version header

### podSecurityContext without runAsUser no longer runs pods as root

A `podSecurityContext` override that omitted `runAsUser` (or set it to null) coerced to
`runAsUser: 0` on idm, ds-cts, and ds-idrepo. Absent values now leave the field unset so the
image's `USER` applies.

### UI preStop hook uses the correct nginx binary path

The UI deployments' preStop hook invoked `/usr/bin/nginx`, which does not exist in the
unprivileged nginx image. It now invokes `/usr/sbin/nginx`, so pods drain correctly.
