# Release Notes

## Kustomize deprecation

Support for Kustomize-based deployments is deprecated. Users should migrate to Helm chart-based deployments.
You can use the <a href="how-tos/migrate-kustomize-to-helm.md">Migrate Kustomize to Helm</a> guide in the ForgeOps repository.

Deprecated in: 2026.3.2

Expected removal: 12 months after 2026.3.2 release

## New Features/Updated functionality

### New secret-agent version

The secret-agent has been patched for security vulnerabilities, and v1.2.14 has
been released.

### New forgeops realm command

Realms are a complicated configuration task, and this new command streamlines
the process for users. More information on using the command can be found in <a
href="how-tos/configuring-realms.md">this guide</a>.

### One POSIX script tree for the Debian and Alpine image lines (FORGEOPS-6971)

`charts/identity-platform/files/` is now the single script tree for both image lines.
Every script runs under dash (Debian `/bin/sh`) and busybox ash (Alpine) alike, and `docker/ds`, `docker/am`,
`docker/idm`, and `docker/amster` vendor byte-identical copies of their chart scripts. The chart now ships the DS
`env.sh` alongside the entrypoint (mounted over the image's copy in both image modes), and the DS statefulsets set
the password-file and PEM-cert-dir environment variables explicitly — an older pinned DS image can no longer
change DS runtime behavior through a divergent baked `env.sh`.

As part of this, the DS JVM defaults are unified on the PingDS upstream values (`MaxGCPauseMillis` 300ms,
`MaxRAMPercentage` 65%, new `InitialRAMPercentage` 65%) in **both** image modes; a `base`-mode deployment that
bumped from the previous defaults (`MaxGCPauseMillis` 200ms, `MaxRAMPercentage` 75%, no `InitialRAMPercentage`)
gets ~10% less max heap. To restore the old behavior or tune the JVM differently, set the corresponding
`DS_JAVA_GC_PAUSE_TARGET` / `DS_JAVA_INITIAL_RAM_PERCENTAGE` / `DS_JAVA_MAX_RAM_PERCENTAGE` environment
variables — `env.sh` reads them with `${VAR:-default}`, so any value set through the `ds_idrepo.env` /
`ds_cts.env` (or `platform.env`) chart values overrides the defaults; the whole argument list can be replaced
with `DS_JAVA_ARGS` (see `files/ds/env.sh` for the full list of tunables it consumes).

### Alpine-based platform images selectable with platform.imageMode

The platform components (AM, amster, DS, IDM, and IG) and UIs (admin-ui, end-user-ui, and login-ui) can now run the
Alpine-based images. Setting `platform.imageMode: forgeops` in the identity-platform chart values switches every
product at once. The default mode (`base`) is unchanged.

Every product image is now resolved through a single chart helper: `platform.imageRepository`
plus a per-component image name, with optional per-component `repository`, `name`, and `tag`
overrides in values.yaml. A `sha256:...` tag renders as a digest reference
(`repository@sha256:...`).

### New RCS Helm chart

A new `charts/rcs` chart deploys the Ping Remote Connector Server in server or client mode:
headless service on port 8759, optional NetworkPolicy allow-listing (`remoteIps`),
ConfigMap-driven `ConnectorServer.properties` and logback configuration, custom connector
libraries, and an optional `rcs-certs` truststore. In server mode the shared `rcs-key` secret is
generated by default; the entrypoint derives the connector-server key from `RCS_KEY_PASSWORD`
(or accepts a pre-computed `RCS_KEY`).

### RCS registers with IDM automatically

When the identity-platform and rcs charts deploy to the same namespace, IDM registers the RCS
out of the box — no manual steps. An optional sample LDAP provisioner
(`platform.rcs.provisioner.enabled`) exposes the deployment's own DS idrepo userstore through
the RCS, giving the admin UI a working connectors entry and a base for sync setup. Stale
registration files are cleaned up on restart when the RCS wiring is off; deployer-supplied
connector configs are left alone.

### ping-gateway ingress forwards the full path (no rewrite-target)

The `ig` ingress now uses a plain `Prefix` path and no longer sets `rewrite-target`: the IG
image strips the `/ig` prefix itself, so ingress controllers that ignore nginx rewrite
annotations work unchanged. `/igadmin` keeps its previous regex + rewrite behavior on a separate
`ig-admin` ingress. If you override `ig.ingress.annotations` yourself, do not set
`rewrite-target`, or requests will be double-prefixed.

## Removed Features

### Removed flags for base-generate.sh

The Kustomize base used to be generated from the Helm chart with
base-generate.sh. The following flags have been removed from the Helm charts.

* platform.base_generate
* keystore_create.force

## Bugfixes

### Amster command now honors bare config-profile names

Providing a bare config profile name to `forgeops amster` did not properly
resolve the path to the config profile. Now, providing just the name of the
config profile properly resolves the path to
`docker/amster/config-profiles/PROFILE_NAME`.

### idm-admin-ui doesn't start with security features

The idm-admin-ui previously listened on port 80 which doesn't work with the
security features enabled. The port has been changed to 8080, and the image was
rebuilt to listen on that port. As part of the upgrade, you need to use
`forgeops image` to select the latest image for idm-admin-ui.

### DS upgrade no longer crash-loops in add-schema when the instance schema lags the binary

On an upgrade with existing data, `add-schema` created `fr-idm-reference-6..10` indexes for
attribute types the persisted instance schema does not define, and `rebuild-index` failed to
decode them, leaving the pod crash-looping. Each attribute is now gated on its presence in the
schema the instance loads, so a schema-lagged upgrade completes and the missing indexes are
created later when the schema catches up. Index configs left behind by the earlier build are
pruned on the first boot of the fixed image; no manual recovery is needed.

### identity-platform amster job no longer mounts the import tarball inside the config directory

The optional `amster-config` ConfigMap's tarball was subPath-mounted at
`/opt/amster/config/amster-import.tar.gz`. When the ConfigMap is absent,
kubelet materialises the missing subPath target's parent directory —
`/opt/amster/config` — as root-owned (`root:root` 0755), and the job's
non-root runtime uid can then not write anything into it: applying the
staged config profile failed with `Permission denied`. The tarball
is now mounted at a neutral path (`/amster-import`) and the init
container copies it into `/opt/amster/config` before the import, so the
ConfigMap's content wins over the image's own config — the same
precedence the in-place mount's extraction had (import.sh extracts the
tarball at import time, overwriting).

### identity-platform keystore secret replaced when stale after a failed install

keystore-create could leave a stale keystore secret after a failed atomic install,  
causing password-mismatch failures. On INSTALL, the init container tests existing  
secrets with the current password, keeping valid ones and replacing invalid ones.  
On UPGRADE, it preserves the secret to avoid silently regenerating JWT-signing and  
IDM keys; operators can opt into replacement with `keystore_create.config.secret.replace: true`.  
Secret creation is now atomic, preventing failed creates from leaving the namespace without  
a secret. The fix applies to Helm only; the deprecated Kustomize overlay retains the old behavior.

### DS init no longer logs add-schema errors on ds-cts

The DS entrypoint ran the per-pod `add-schema` script unconditionally, logging
`No such file or directory` on every ds-cts boot. The add-schema script ships for ds-idrepo only; the call
is now guarded.

### DS snapshot cron job works on busybox and releases cloned PVCs

`snapshot.sh` used GNU-date-only invocations and a redirection instead of a comparison
(`[ $# > 0 ]`), so on the busybox cronjob image the purge loop was broken. The script now
detects the date implementation and parses the documented relative expressions
(`last day`, `last hour`, `-10 min`) on busybox. The backup job is also deleted after a
successful snapshot so the cloned PVC is released.

### rcs chart hardening

* The StatefulSet now sets `serviceName` (required before Kubernetes 1.34, and what provides
  per-pod DNS)
* Secret volumes are readable by the non-root runtime uid (mode 0444)
* The NetworkPolicy uses the chart's own selector, admits same-namespace consumers alongside
  `remoteIps`, and allows DNS over TCP
* A `checksum/config` annotation rolls the pods when the rendered config changes
* `RCS_KEY` is JSON-escaped before being written into IDM's registration config
* `capabilities.drop` uses Kubernetes' `ALL` token instead of the invalid `All`
* The chart-publish workflow can no longer publish the placeholder-versioned platform charts or
  a broken chart from an unreadable version header

### podSecurityContext without runAsUser no longer runs pods as root

A `podSecurityContext` override that omitted `runAsUser` (or set it to null) coerced to
`runAsUser: 0` on idm, ds-cts, and ds-idrepo. Absent values now leave the field unset so the
image's `USER` applies.

### UI preStop hook uses the correct nginx binary path

The UI deployments' preStop hook invoked `/usr/bin/nginx`, which does not exist in the
unprivileged nginx image. It now invokes `/usr/sbin/nginx`, so pods drain correctly.
